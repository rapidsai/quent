<objective>
Add the two-pass handle-resolution layer (D-15) to the reconstruction core: pass 1 scans all
events (order-independent, tolerating forward references) to build lookup tables; pass 2 resolves
each span/mark's label. Registered strings key by `(domain, handle)` (ANA-01); category names key
by `(domain, categoryId)` — NEVER globally (ANA-02); domain and thread names resolve too. Unresolved
handles get stable, deterministic placeholders that surface the raw id (D-14, success criterion 2).
Marks, domains, threads, and categories become first-class in the model (MOD-02).

Purpose: turn raw-integer-handle spans into labeled, groupable entities.
Output: resolved names on spans + marks/domains/threads/categories in the model.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Spoofing / Information Disclosure | placeholder formatting of unresolved handles | mitigate | Placeholders are pure functions of the raw id (hex), never interpolate attacker-controlled strings into format specifiers; unresolved names stay visibly quoted (`<...>`) so they cannot masquerade as real labels. |
| T-02-05 | Denial of Service | resolution-table growth on a stream with vast distinct handles | accept | Bounded by the finite captured session; same rationale as T-02-02. |
| T-02-01 | Denial of Service | forward-reference / missing-registration handling | mitigate | Two-pass build tolerates forward refs; missing registrations resolve to placeholders (never `unwrap`/panic). |
</threat_model>
