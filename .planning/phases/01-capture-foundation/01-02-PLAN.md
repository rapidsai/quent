<objective>
Build `quent-nvtx-injection`: the Quent-agnostic cdylib NVTX loads via
`NVTX_INJECTION64_PATH`. It exports `InitializeInjectionNvtx2`, fills the CORE/CORE2
callback tables one-shot, converts push/pop NVTX calls to verbatim `NvtxEvent`s, and
hands them to a sink-agnostic `Fn(NvtxEvent)` hook (D-03/D-15). This plan wires the FFI
skeleton and ONE representative event kind (push/pop) end-to-end at the callback layer;
plan 04 widens to the remaining kinds. Header sourcing is a pinned NVIDIA/NVTX git-dep
(D-13) used ONLY to regenerate bindings; the generated bindings are committed so default
and CI builds are hermetic (D-14).

Purpose: Prove the real attach path (CAP-01) and verbatim conversion (CAP-02/CAP-03)
that uninstrumented GPU libs require, de-risking Phase 5.
Output: `integrations/nvtx/injection/` cdylib + committed bindings + deny.toml edit.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| NVTX C ABI → Rust callback | NVTX passes `const char*` and raw handles; caller-owned, valid only for the call duration; effectively untrusted foreign input. |
| Rust callback → C caller (return) | A Rust panic must never unwind across this boundary. |
| Build-time header source | NVTX headers fetched from a pinned NVIDIA/NVTX git rev ONLY under the regenerate-bindings feature; bindgen consumes them. Default builds use committed bindings. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Denial of Service | every `extern "C"` callback in callbacks.rs | mitigate | Wrap each callback body in `std::panic::catch_unwind`; never propagate a panic into C (UB → app crash). |
| T-02-02 | Tampering / DoS | caller-owned `const char*` message args | mitigate | Copy message bytes into owned `String` inside the callback before returning (Pitfall 3 UAF). |
| T-02-03 | Information disclosure / DoS | reading `nvtxEventAttributes_t` members past `size` | mitigate | Branch on `version`/`size`; read only declared members (Pitfall 4, ASVS V5 input validation). |
| T-02-04 | Elevation of trust boundary | `.so` injected via `NVTX_INJECTION64_PATH` | accept | Injector loads only into opt-in processes; no elevated behavior; documented trust boundary (RESEARCH Security Domain). |
| T-02-05 | Spoofing / Tampering | strong-symbol override of NVTX weak symbol (static path) | accept | Feature-gated `static-injection` only; runtime cdylib path is primary and linkage-order-independent (Pitfall 5). |
| T-02-SC | Tampering | NVTX git-dep + bindgen/cc/cargo_metadata installs | mitigate | Package Legitimacy Audit (RESEARCH.md) returned `[OK]` for bindgen, cc, crossbeam-queue, cargo_metadata — no `[ASSUMED]`/`[SUS]`, no blocking checkpoint required. NVTX source is feature-gated (not fetched by default builds), pinned to `rev = "<sha>"`, and allow-listed in deny.toml; `cargo deny check` is a phase gate. |
</threat_model>
