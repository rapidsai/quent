<objective>
Build `quent-nvtx`: the bridge that fronts Quent's unbounded `EventSender` with a bounded,
lock-free `crossbeam-queue::ArrayQueue` + drop-and-count + drain thread (D-16/D-07), stamps
each `NvtxEvent` with a capture timestamp via `Event::new_now` (CAP-04), and wires the
injection hook. Then PROVE the thinnest real end-to-end capture path: a deterministic
push/pop test-app emits NVTX through the actual ndjson exporter, and a subprocess harness
reads the file back and asserts push/pop events with timestamps arrived (CAP-01/VAL-01/VAL-02).

This is the MVP walking-skeleton of capture — after this plan a real developer can attach the
injection library to an app and see NVTX events land in an ndjson file. Plan 04 widens coverage.

Purpose: First observable end-to-end capability + the CAP-05 hot-path discipline proof.
Output: `integrations/nvtx/instrumentation/` bridge + test-app bin + subprocess e2e test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| injection hook → bounded ring | Events arrive on the app thread; the ring is the non-blocking hand-off. |
| drain thread → EventSender | Off the app thread; the only crate touching Quent internals. |
| subprocess ndjson file → harness | Test reads back captured data as bytes; no code execution. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Denial of Service | unbounded allocation under high-frequency emission (OOM the app) | mitigate | Bounded `ArrayQueue` + drop-and-count in front of the unbounded EventSender (CAP-05, D-16); producer never blocks. |
| T-03-02 | Denial of Service | producer blocking on a full/backpressured sink | mitigate | Never feed capture into the collector client's bounded-blocking mpsc; keep capture on ring→`EventSender::send` (non-blocking). Drain runs off the app thread. |
| T-03-03 | Tampering | ndjson deserialization in the harness | accept | Test-only file produced by the same process; not untrusted input. |
| T-03-SC | Tampering | crossbeam-queue install | mitigate | `crossbeam-queue` returned `[OK]` in RESEARCH.md Package Legitimacy Audit — no `[ASSUMED]`/`[SUS]`; no blocking checkpoint required. |
</threat_model>
